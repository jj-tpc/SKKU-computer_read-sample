# 시험 방법 정하기

Type: grilling
Status: resolved

## Question

새 프로그램을 어떻게 시험하나? [Qt로 바꾼 뒤의 프로그램 구조 정하기](16-grilling-program-structure.md)에서 `ui/` 밖의 모듈은 화면 없이 pytest로 시험할 수 있게 나눴다. 지금 `tests/`에는 세 파일(`test_app_logic.py`, `test_slides.py`, `test_tts.py`)이 있다.

정할 것:
- **자동 테스트로 덮을 범위**: `qa`(근거 묶음, 지침 합치기, 대화 기억 6번, 문장 자르기), `llm` 어댑터(가짜 응답으로 스트림과 다섯 오류 바꾸기), `voice`(크기 곡선, 입 모양 판정, 블루투스 무음 길이, 배속 배율 나누기), `captions`(그림 꺼내기, 해시 저장, 상한), `settings`(옛 파일 옮기기), 강아지 따라가기 계산(가장자리, 모니터, 원 버튼 옆 자리).
- **기존 테스트**: tkinter 화면을 전제로 한 `test_app_logic.py`를 어떻게 바꾸나. Qt 화면 로직을 pytest-qt 같은 것으로 시험하나.
- **실제 LLM 호출**: 키가 있을 때만 도는 시험을 두나. 비용은 어떻게 막나.
- **사람이 확인할 목록**: 실제 PowerPoint 쇼 위에서 확인할 것(Windows는 발표자가, macOS는 받는 사람 확인표로), x5 음질, 블루투스 장치.
- **빌드 서버에서 돌릴 것**: [실행 파일 빌드와 넘기기 정하기](17-grilling-build-and-handoff.md)의 `--self-check`와 pytest를 함께 돌리나.

## Answer

- **자동 테스트(pytest)**: 화면, 인터넷, 소리 없이 돈다. 시간이 걸리는 규칙은 가짜 시계로 시험한다. `pytest`, `pytest-qt`는 개발용 의존성으로 따로 둔다.

| 모듈 | 시험할 것 |
|---|---|
| `qa` | 근거 묶음의 내용과 순서(바뀌지 않는 부분이 앞), 지침 합치기 규칙, 대화 기억 6번과 "(끊김)" 표시, 문장 자르기("3.5배" 같은 숫자와 따옴표에서 안 잘리기) |
| `llm` | 가짜 SDK 응답으로 세 어댑터 시험: 글 조각 흐름, 생각 조각 걸러 내기, mid → medium, SDK 오류를 다섯 공통 오류로 바꾸기 |
| `voice` | 가짜 소리로 크기 곡선 만들기, 입 모양 판정(20%·55%, ㅐ ㅒ ㅔ ㅖ ㅢ ㅣ 가로 입, 60ms 유지), 블루투스 무음 길이 × 배율, 엔진 배속과 늘이기 배율 나누기, macOS 낱말 시각 어림 |
| `captions` | 시험용 PPT를 코드로 만들어 그림 꺼내기, 작은 그림과 반복 로고 빼기, 해시로 다시 쓰기, 고친 캡션 안 덮어쓰기, 40개 상한, 1024px 줄이기 |
| `settings` | 옛 설정 파일 옮기기, 고친 대본 저장과 "원본이 바뀌었어요" 판정, 생각 깊이는 켤 때마다 low |
| 강아지 따라가기 | 계산을 따로 함수로 만들어 시험: 가장자리에서 반대쪽, 다른 모니터면 원 버튼 옆 자리, 원 버튼 묶음 위면 대기, 속도 공식 |
| 오류 반응 | 가짜 시계로 8초·30초 기다림 말, low 45·mid 90·high 150초 시간 초과, 30초 멈춤 |

- **기존 테스트**:
  - `test_slides.py`는 그대로 둔다.
  - `test_tts.py`는 `voice/` 시험으로 옮긴다.
  - `test_app_logic.py`(tkinter)는 버린다. 대신 읽기 흐름, 자동 발표, PowerPoint 따라가기, 질의응답 흐름 같은 상태 묶음을 Qt를 모르는 **`session.py`**로 빼고, 일곱 시험을 가짜 음성·연동·LLM으로 그쪽에 옮긴다. `ui/app.py`는 신호만 잇는다.
- **Qt 테스트**: pytest-qt로 몇 개만 둔다. offscreen 모드에서 창이 뜨는지, 위성 버튼을 누르면 `session`이 불리는지 본다.
- **실제 LLM 시험**: `live` 표시를 단 시험은 키를 환경 변수로 줬을 때만 돈다. 제공자마다 기본 모델, 생각 깊이 low로 짧은 질문 하나와 작은 그림 캡션 하나만 보낸다. 공개 저장소의 빌드 서버에는 키를 두지 않으므로 거기서는 돌지 않는다.
- **사람이 확인할 목록**: 기획서 부록에 둔다.
  - Windows(발표자가 넘기기 전에 이 PC에서): 모니터 두 대에서 실제 PowerPoint 쇼 위에 보이는지, 클릭 통과, 포커스 안 뺏기, 질문창 한글 입력, 말풍선과 입 모양이 목소리와 맞는지, x5 음질, 블루투스 첫마디, 세 제공자 질의응답, 틀린 키·인터넷 끊김 오류, 캡션.
  - macOS: [실행 파일 빌드와 넘기기 정하기](17-grilling-build-and-handoff.md)의 받는 사람 확인표.
- **빌드 서버**: 두 운영체제에서 pytest를 먼저 돌리고, 통과하면 빌드한 뒤 `--self-check`를 돌린다. macOS는 화면 찍기까지 한다.
